Claude Code スキル紹介

Claudeの第一声を信じるな。
自分自身に議論させろ。

「このアイデア、良いと思う？」とClaudeに聞くのは、もう終わりにしませんか。考え方の違う5人のAIに議論させて、お互いの意見を誰のものか分からない状態でチェックさせて、最後に筋の通った答えだけを受け取る。それが Claude Council です。

THE PROBLEM

Claudeは、とにかく同意したがるんです。

正直に言うと、私はこれで何度か痛い目を見てきました。「このプロダクト、ローンチすべきかな？」とClaudeに聞くと、やるべき理由を5つ並べてくれる。じゃあ試しに「このプロダクトって微妙かな？」と聞き方を変えてみると、今度はダメな理由を5つ並べてくる。

メールの文面を考えてもらうくらいなら、それで全く問題ありません。でも、値段を変える・新しく何かを始める・やり方を大きく変える、といった判断でこれをやると、結構危険なんですよね。自分が聞きたい答えを、そのまま返してもらっているだけになりかねないので。

Claude Council というスキルは、この問題そのものを解決してくれます。やり方はシンプルで、Claudeに自分自身と議論させるんです。5人の違う考え方を立てて、誰の意見か分からない状態でお互いにチェックさせ、最後に1人のまとめ役が結論をまとめる ― という流れです。

WHAT YOU GET

「council this」と打つだけで、6ステップが自動で走ります。

状況を集める

作業中のファイルや設定など、関係がありそうな情報を集めます。

質問の偏りをなくす

投げかけた質問を、答えを誘導しない、まっすぐな聞き方に整え直します。

5人を同時に動かす

考え方の違う5人を、同時に立ち上げます。

誰か分からない状態でチェックし合う

誰の発言かを隠したまま、5人がお互いの意見を読んで感想を言い合います。

まとめ役が結論を出す

みんなが賛成した点・意見が割れた点・見落としていたこと・次にやることを、1つにまとめます。

記録を作る

見やすいレポート（HTML）と、やり取り全部の記録（文章ファイル）を書き出します。

全部で、約4分。ここまでを1セッションでやってくれます。

THE 5 ADVISORS

根本的に違う、5つの角度から見る。

ただのキャラ付けではありません。お互いにぶつかり合うように、あえて考え方を分けて作られています。

危ないところ探し反対者 The Contrarian
どこが間違っているか、何が足りないかを進んで探します。「このアイデアには必ず弱点がある」と決めつけて、それを見つけ出す役です。
問い直す人第一原理思考家
表面的な質問はいったん置いておいて、「本当に解決したいのは何か」を考え直します。思い込みを取り払って、ゼロから考える役です。
チャンス探し拡張主義者
みんなが見逃しているチャンスを探します。もっと大きくできないか、もっと伸びしろがないか。危ないところ探しは反対者の仕事なので、気にしません。
初めて聞く人部外者 The Outsider
あなたの仕事やこれまでの経緯について何も知らないつもりで話します。自分には当たり前でも、他の人には伝わらないことに気づかせてくれる役です。
とにかく動く人実行者 The Executor
気にするのは「月曜の朝、何をやるか」だけです。話がどれだけ立派に聞こえても、次にやることがはっきりしていなければ、それをそのまま指摘します。

この5人の間には、3つの対立軸があります。

反対者（危ないところを見る） ⟷ 拡張主義者（チャンスを見る）
第一原理思考家（考え直す） ⟷ 実行者（すぐ動く）
部外者は真ん中に立って、みんなに正直でいさせる役です。
EXAMPLE

同じ問いに、5つの答え。

たとえば「パソコンが得意でない人向けに、初心者用の講座を作るべきか」という質問を投げると、こんな感じになります。

反対者

すでに似たような講座はたくさんあるので、他との違いを出すのが難しい。パソコンが得意でない人向けだと、質問対応の手間も、お金を返してほしいと言われる可能性も高くなりそう ― という角度から疑ってかかります。

第一原理思考家

そもそも本当にほしいのは売上なのか、信頼されることなのか、それとも高いサービスにつなげる準備なのか。目的によっては、「講座を作る」というやり方自体が合っていないかもしれない、と考え直します。

拡張主義者

初心者×パソコンが得意でない人、という組み合わせはまだ誰も手を付けていない可能性がある。値段はむしろ安すぎるかもしれない、とチャンスの大きさに目を向けます。

部外者

その講座の名前を見ても何のことか分からない、という初めて聞く人の目線から、「見出しがやり方の名前になっていて、得られる結果が伝わっていない」ことを指摘します。

実行者

いきなり講座を作り込む前に、まず安いライブ講座で実際に売れるか試すべきだ、と最初の一歩だけに話を絞ります。

▲ まとめ役の結論（イメージ）

みんなが賛成した点

この組み合わせ自体には見込みがあるが、今の見せ方はやり方の名前に寄りすぎていて、パソコンが得意でない人には伝わりにくい。

見落としていたこと

「その名前は誰にでも伝わる」と、部外者以外の全員が気づかないうちに思い込んでいたこと。

最初にやる1つのこと

本講座を作り込む前に、気軽に試せる安いサービスで実際に売れるか試してみる。

※上記は使い方のイメージを伝えるための一例です。実際の答えは、投げかける質問やその時の状況によって変わります。

INSTALL

必要なのは、コマンドを打つ画面だけです。

必要なのは3つだけ。Claude Codeが使える状態になっていること、コマンドを打つ画面（ターミナル）が開いていること、以上です。

方法1：Git Clone（推奨） 
git clone https://github.com/tenfoldmarc/llm-council-skill ~/.claude/skills/llm-council

あとはターミナルで claude と打ってClaude Codeを開けば終わりです。このスキルは ~/.claude/skills/ という共通の場所に入るので、パソコン上のどのプロジェクトでも使えます。プロジェクトごとに入れ直す必要はありません。

HOW TO USE

合言葉のあとに、聞きたいことを書くだけ。

次のどれかの言葉のあとに、聞きたいことを続けてください。

council this ／ run the council ／ pressure-test this ／ stress-test this ／ war room this ／ debate this

入力例 
council this: パソコンが得意でない個人事業主向けに、
¥29,800の講座から¥9,800のライブ講座へ
やり方を変えようと考えている。これは正しい判断か？

コツは、状況を惜しみなく伝えること。数字・制約・すでに試したことを書くほど、返ってくる意見が鋭くなります。

THE OUTPUT

2つのファイルが出てきます。

📊
council-report-[ts].html
見やすく整理されたレポート。まとめ役の結論、賛成／反対のまとめ、5人それぞれの意見、お互いのチェック内容が折りたたみ式で入っていて、できあがると自動で開きます。
📝
council-transcript-[ts].md
5人の意見とお互いのチェック内容を、すべてそのまま残した記録ファイル。あとから読み返して、考えがどう変わっていったかを確認できます。
WHEN TO USE

向いている問い、向いていない問い。

✓ councilに向いた質問

  • 2つの選択肢、どちらを選ぶべきか迷っている
  • いくつかの案のうち、どれが一番いいか知りたい
  • 大きくやり方を変えようとしていて、大丈夫か確かめたい
  • 書いた文章の弱いところを見つけてほしい
  • 人を雇うか、先に仕組みを作るか迷っている

× 使わない方がいい時

  • 答えが1つに決まる、事実の確認だけをしたいとき
  • 文章を書いてほしいだけの作業
  • 要約や整理だけをしてほしいとき
  • すでに答えは決めていて、ただ背中を押してほしいだけのとき

councilは、聞きたくないことも遠慮なく言ってきます。それは不具合ではなく、そういう作りです。

PRO TIPS

使いこなすための5つのコツ。

1

状況を惜しみなく伝える。数字・制約・すでに試したことを書くほど、話し合いの質が上がります。

2

大きな決断の前に使う。値段を変える・新しく始める・人を雇う・やり方を大きく変える、など間違えると痛い判断ほど役に立ちます。

3

まず「初めて聞く人」の意見から読む。自分がよく知りすぎていて気づけない部分を、一番意外な角度で教えてくれるからです。

4

まとめ役は、多数派に逆らうこともあります。4人が「やるべき」と言っても、反対者の理屈のほうが筋が通っていれば、まとめ役はそちらを支持します。これはあえてそうなる作りです。

5

記録は保存しておく。状況を変えてもう一度同じ質問をすると、前回との違いから自分の考えの変化が見えてきます。

こんな感じでを賢く使うことで誰でも副業が始められちゃいます！
